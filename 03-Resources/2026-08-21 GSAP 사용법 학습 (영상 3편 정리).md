## 1. 기본 문법 (영상 1, 2 공통)

- **설치**: CDN `<script>` 태그를 본인 스크립트(`script.js`) 태그보다 **먼저** 배치해야 함 — 순서를 지키지 않으면 `gsap`이 정의되지 않은 상태에서 코드가 실행됨.
- **`gsap.to(selector, {...})`**: 현재 상태 → 지정한 값으로 애니메이션.
- **`gsap.from(selector, {...})`**: 지정한 값(예: 화면 밖) → 현재(CSS 기본) 상태로 애니메이션. 요소가 이미 최종 위치에 있을 때 "그 위치로 들어오는" 연출에 편리.
- **`gsap.fromTo(selector, {from...}, {to...})`**: from/to 값을 모두 명시 — CSS 기본값에 의존하고 싶지 않을 때.
- **`duration`**(초 단위 애니메이션 길이) vs **`delay`**(애니메이션 시작 전 대기 시간) — 두 개념이 자주 헷갈림. 영상 1의 비유: "본포에서 델리까지 이동 시간=duration, 출발 전 대기 시간=delay".
- **CSS 프로퍼티는 camelCase로**: `background-color` → `backgroundColor`, `border-radius` → `borderRadius`. 특수문자가 들어간 값(`"50%"` 등)은 문자열로 따옴표 필요.
- `x`, `y`, `rotate`, `scale` 같은 transform 계열 속성은 GSAP이 자동으로 `transform: translateX() rotate() scale()`로 묶어서 처리 — CSS에 별도 transform 속성을 안 만들어도 됨.
- **`stagger`**: 같은 선택자에 걸리는 여러 요소를 순차적으로 시간차를 두고 실행. `stagger: 0.5`면 요소마다 0.5초씩 밀려서 시작.
- GSAP은 DOM 요소뿐 아니라 **순수 JS 객체**도 애니메이션 가능(`gsap.to(obj, {x:100, onUpdate:()=>{...}})`) — 대시보드에서 헤드라인 숫자 카운트업 만들 때 쓴 방식이 바로 이 패턴.

## 2. 타임라인 (`gsap.timeline()`)

- 여러 애니메이션을 순서대로 묶어서 관리 — `duration`/`delay`를 개별로 흩어놓으면 하나 바꿀 때 나머지가 다 깨지는 문제를 해결.
- `const tl = gsap.timeline({ defaults: { duration: 1 } })` — 공통 기본값을 한 곳에서 관리.
- `.from()`, `.to()`를 **체이닝**해서 이어붙이면 자동으로 이전 애니메이션이 끝난 뒤 다음이 시작됨.
- **포지션 파라미터**(각 호출의 두 번째 인자)로 타이밍 제어:
  - 절대값(숫자): 타임라인 시작 기준 몇 초 뒤
  - `"<"`: 바로 이전 애니메이션이 **시작한 시점** 기준(+오프셋 가능, 예: `"<0.5"` = 이전 시작 0.5초 후)
- **`tl.reverse()`**: 타임라인 전체를 역재생 — 버튼 클릭 한 번으로 전체 시퀀스를 되돌릴 수 있어 "리버스 버튼" 같은 UI에 매우 간단하게 적용 가능.
- **`tl.timeScale(3)`**: 재생 속도를 3배로(역재생 시 빠르게 되돌리는 연출에 사용).

## 3. ScrollTrigger (영상 3 중심)

- 플러그인이라 GSAP 코어 CDN과 별도로 ScrollTrigger CDN을 추가로 불러와야 함.
- `gsap.timeline({ scrollTrigger: { trigger: '.el', start: 'top center', end: 'bottom center', scrub: true, markers: false } })` 형태로 타임라인 안에 정의.
- **`trigger`**: 스크롤 기준이 되는 DOM 요소.
- **`start` / `end`** 문자열은 `"[트리거 요소 기준점] [뷰포트 기준점]"` 형식. 예: `"top center"` = 트리거 요소의 top이 뷰포트의 center에 닿을 때. `top`/`center`/`bottom`뿐 아니라 `"20%"`, `"-50%"`, 픽셀값도 가능 — 값을 조정해 애니메이션이 시작/끝나는 스크롤 위치와 소요 구간을 정밀 제어.
  - start와 end를 서로 가깝게 하면 애니메이션이 빨리 끝나고, 멀리 벌리면 느리게 진행됨(스크럽 상태일 때).
- **`markers: true`**: 화면에 start/end 지점을 시각적으로 표시 — 디버깅 시 필수, 완성 후엔 false로.
- **`scrub: true`**: 애니메이션 진행률이 **스크롤 위치에 직접 연동**(스크롤을 멈추면 애니메이션도 멈춤). `scrub: false`(기본값)면 트리거 지점을 지나는 순간 `duration`에 정의된 시간만큼 독립적으로 재생됨(스크롤과 무관하게 흘러감).
- **`toggleActions`**: `scrub:false`일 때만 의미 있음(`scrub:true`면 무시됨). `"onEnter onLeave onEnterBack onLeaveBack"` 4개 값을 공백으로 구분해서 지정하며, 각 값은 `play`/`pause`/`resume`/`reverse`/`restart`/`complete`/`none` 중 선택:
  - onEnter: 아래로 스크롤하며 요소가 뷰포트에 들어올 때
  - onLeave: 아래로 스크롤하며 요소가 뷰포트를 벗어날 때
  - onEnterBack: 위로 스크롤하며 다시 들어올 때
  - onLeaveBack: 위로 스크롤하며 다시 벗어날 때

## 대시보드 작업과의 연결

오늘 토큰 사용량 대시보드에 적용한 `ScrollTrigger.batch(".callout, .rule", { start: 'top 85%', once: true, onEnter: batch => gsap.from(...) })` 패턴은 이 영상들에서 배운 `trigger`/`start`/`onEnter` 개념의 실전 응용이다. `once:true`는 `toggleActions`의 `onLeaveBack`을 `none`으로 고정하는 것과 유사한 효과(한 번 재생되면 되감기지 않음).
