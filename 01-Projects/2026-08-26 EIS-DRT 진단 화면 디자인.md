- JSON 계약: meta{filename, temp_C} + nyquist 원시배열 + drt{tau, gamma, lambda, cutoff_hz, peaks[]} + features{R_s, R_ct} (+ 미래: diagnosis) — 단위 Ω, mΩ 변환은 프런트

## ★ 엔진 검증 요청 — τ축 shift 관련 (2026-08-31, 다음 엔진 세션이 처리할 것)
배경: 현 판정 기준은 진폭 축(R_ohm·R_SEI·R_ct·R_diff)+KK 잔차뿐 — DRT 피크의 τ 방향 이동 정보가 판정에 미반영. τ=R·C이므로 피크 이동은 정전용량·동역학 변화(조기 열화 신호) 또는 측정 조건 차이(온도)를 의미.
1. **Δlog τ 특징 추출**: 기준 대비 각 피크의 τ 위치 이동량을 특징값으로 추출, JSON 계약의 features에 추가 (peaks[]에 tau 있음 → 기준 정렬 후 편차 계산)
2. **피크 매칭 방식 검증**: P1/P2/P3 할당이 절대 τ 구간 기준이면 전역 shift 시 라벨 오배정 위험 — 상대 순서·기준 스펙트럼 정렬 기반인지 재확인
3. **λ 인공 shift 검증**: 파일별 자동 λ(L-curve) 차이가 피크 위치를 인위적으로 이동시키는지 확인 (동일 데이터에 λ 스윕해서 피크 τ 안정성 체크)
4. **전역/국부 구분 로직**: 전 피크 일괄 이동(→온도 등 측정 조건 의심, 품질 플래그) vs 특정 피크만 이동(→해당 계면 열화, 판정 특징) 분리. 온도 미기록(0/null) 파일에서 전역 shift 시 "측정 조건 확인" 플래그 출력
- UI 쪽은 표시 자리 준비됨(기여도 항목·품질 칩·피크 궤적 뷰) — 엔진 출력이 오면 연결만 하면 됨

## ★ 엔진 통합 대비 디자인 수정 목록 (2026-09-01, Zhang 외부 검증 결과 반영)

배경: 엔진 세션이 Zhang et al. 2020(Nat. Commun. 11, 1706) 실측 EIS로 외부 검증 완료(커밋 2c2d687, agentmemory `mem_mtgxccex_0dac9a0b7728`). 디자인에 영향 주는 확정 사실: TAU_BEYOND_WINDOW 경고 신설(품질 경고가 KK 단일→목록), EOL 국면 전환에서 피크 7개까지 실측, "고정 τ-창 피크 매칭은 취약 — 열화 피처는 피크 위치보다 대역별 저항 질량", peak_regions argmin 분할로 피크 면적 합=Rp 보장, τ shift는 실제 열화 신호로 검증(전하이동 피크 τ 2배 이동), 실측 R0=1774 mΩ 사례(극단값도 정상 데이터).

### 통합 전 필수
1. **품질 칩 → 경고 목록 구조**: 최고 심각도 + 개수 표시("경고 2건"), 펼치면 목록. 경고 코드→한국어 문구 매핑표 정의 (TAU_BEYOND_WINDOW → "측정 범위 밖 시상수 — 외삽 구간" 등) → **✅ 시안 반영 완료 (2026-09-02)**: 0/1/2건 상태·팝오버 목록 캡처 검증
2. **피크 5~7개 상태 설계**: P-라벨 매칭 무의미 국면 → 개별 라벨 포기, τ 대역 밴드 + "확산 지배 국면 전환" 배지로 전환 (EOL 판정 근거로 표출)
   → **⏸ 보류 + 엔진 재검토 요청 (2026-09-02, 디자인→엔진)**: 사용자 지적 — 합의 사양은 피크 1~4까지였다. 원안대로 "5개 이상=EOL 국면 전환 레드 배지"를 넣으면 **정상 셀 N-9(λ 붕괴 스파이크 7개)이 EOL 배지를 달게 되는 오진** — Zhang EOL 7개와 λ 붕괴 아티팩트 7개를 피크 개수만으로 구분 불가. 엔진에 질문 4건:
   (1) `peaks[]` 출력 개수에 내부 상한이 있나(4개 cap? 무제한?) — N-9_1 JSON의 peaks 배열엔 실제 몇 개가 실리나
   (2) 피크 5개 이상일 때 "진짜 확산 지배 전환" vs "λ 붕괴 아티팩트"를 엔진 신호로 구분 가능한가 (λ 붕괴 시 lambda_reliable=false 또는 LAMBDA_* 경고가 항상 동반되나? 동반된다면 UI는 그걸로 분기 가능)
   (3) "축퇴 기준 1 decade 강화 예정"(합의 사양)은 적용됐나 — 적용되면 5개 이상 출력 자체가 실질적으로 사라지나
   (4) 디자인 수정안에 대한 의견: 피크 ≥5이면 P-라벨 숨기고 대역 밴드 표시로 전환하되, **EOL 배지 대신** (a) λ 신뢰 플래그·경고가 있으면 품질 경고("피크 분해 불안정")로, (b) 경고 없이 5개 이상이면 그때만 "확산 지배 국면 전환 가능성" 문구(단정 금지)로 표기 — 이 분기가 엔진 출력과 정합한가
   → UI 프롬프트 2는 엔진 답변 후 재작성
3. **축·컬러바 극단값 대응**: 자동 스케일 + 이상치의 컬러바 압축 방지 규칙 (퍼센타일 클램프 + 범위 밖 마커) → **✅ 시안 반영 완료 (2026-09-02)**: 극단값 데모 셀 CELL-F01(1774 mΩ, 엔진 N-1 실측 사례 구조) 추가, "▲ 축 범위 밖 1개" 마커·클램프 캡처 검증
7. **판정 4종 상태 설계** (2026-09-02 추가, classifier_v2 반영): 기존 정상/주의/불량 3종 → 엔진 판정은 정상/불량/**판정불가**/**측정 재시도 필요** 4종 + 불량확률(proba)·임계(low/high). "판정불가"=확률이 low~high 사이(임계 동봉이라 게이지로 시각화 가능), "측정 재시도 필요"=품질 문제로 판정 자체 무효. 배지·목록 아이콘·필터 칩·기여도 패널·리포트 전부에 두 상태 추가 필요. 주의(앰버)와 판정불가의 관계 정의도 필요(주의=UI 자체 분류인지 엔진 판정과 별개 축인지 확정할 것)
   → **✅ 엔진 답변 (2026-09-02)**: "주의"는 엔진 판정 축에 존재하지 않는다 — 판정 배지에서 주의 상태를 **제거**할 것. 앰버는 품질 축 전용(`quality.overall=WARN` / `quality.warnings[]` — 합의 사양대로 양불 판정과 분리된 축)으로만 쓴다. 판정불가 ≠ 주의: 판정불가는 확률이 low~high 사이라는 판정 축의 정식 상태(게이지 시각화 가능). "측정 재시도 필요"는 피처 추출 실패(스펙트럼이 DRT 파이프라인 처리 불능)일 때만 나오며 이때 **`proba: null`** — proba가 null인 유일한 verdict이므로 UI는 이 상태에서 확률 게이지를 숨겨야 한다. 즉 한 셀 = 판정 배지(4종) × 품질 칩(PASS/WARN/FAIL) 2축 조합이고, "정상인데 WARN"(N-1 샘플이 실례) 같은 조합이 실제로 나온다
   → **✅ 시안 반영 완료 (2026-09-02)**: 다크·라이트·리포트 3파일 2축 전환(판정 정상●인디고/불량✕레드/판정불가◆그레이퍼플/재시도↻그레이 + 품질 앰버 보조), "주의" 문자열 3파일 0건, 판정불가 확률 게이지(임계 눈금 2개)·재시도 패널(proba 숨김)·정상×WARN 조합 캡처 검증. 구현 단계 참고: 30셀 실제 PDF 생성 시 리포트 렌더 성능 점검 필요(디자인 에이전트 지적)
