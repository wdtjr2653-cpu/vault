## 엔진(drt_analysis, vault-36 세션)과 합의된 사양
- 저주파 처리: **KK 잔차 기준 파일별 자동 컷오프**(고정 10mHz 아님 — 데이터 하한 ~1Hz), extended DRT 불필요(확산 검출 281건 중 1건)
- λ: L-curve 파일별 자동(고정 표기 금지), 파일별 값+신뢰 플래그 표시
- 피크 개수: 1~4 가변(실제는 2~3 대부분 전망, 축퇴 기준 1 decade 강화 예정), R_diff "측정 범위 내 미검출" 상태 필요
- 데이터 없는 필드: SoC·사이클·measured_at 없음. ~~SoH 모델·분류기 미구현 → "모델 준비 중" placeholder~~ → **분류기 완성(2026-09-01, classifier_v2)**: 판정 4종(N/불량/판정불가/측정 재시도 필요) + 불량확률 + 임계(low/high). 불량 재현율 100%(셀 단위 그룹 CV). placeholder는 "모델 파일 없음" 폴백(diagnosis:null)일 때만
- 품질 배지: 대표 라벨 "수치 신뢰도", 펼치면 KK 정합성(PASS/WARN/FAIL)·식별 가능성 — 양불 판정과 분리된 축
- 온도: null 또는 0이면 "—"(미기록) 표시
- JSON 계약: meta{filename, temp_C} + nyquist 원시배열 + drt{tau, gamma, lambda, cutoff_hz, peaks[]} + features{R_s, R_ct} (+ 미래: diagnosis) — 단위 Ω, mΩ 변환은 프런트

## ★ JSON 계약 구현 완료 (2026-09-01, 엔진 커밋 `21a791d`) — UI 연결 준비됨
- `analysis_pipeline.export_json(csv경로, 출력경로)` — 최상위 6키: `meta / nyquist / drt / features / quality / diagnosis`
- **diagnosis는 최상위**(사용자 결정): `{verdict, proba, thresholds{low, high}}` — 임계를 동봉했으니 판정불가는 "확률이 low~high 사이"로 시각화 가능. 모델 파일 없으면 `null`(이때만 "모델 준비 중")
- 합의 계약에서 확장된 부분: `nyquist`에 fit 배열 포함(`zreal_fit_ohm`/`zimag_fit_ohm`) · `drt.lambda_reliable`(최대측+**최소측 λ 붕괴** 합성, 2026-09-01 신설 플래그) · `features`에 `R_diff_ohm`/`Rp_ohm`/`L0_H`, **`delta_log_tau: null` 자리 예약**(τ shift 검증 요청 1번 — 미구현, 구현되면 채움) · `quality{overall, separation, issues[{code, level, message}]}`
- NaN/inf → null. 온도 전부 0 → `meta.temp_C: null`
- **실측 샘플 3종 생성됨**: `scratchpad\json_samples\` — N-1_1(정상, λ 최대측 경계 FAIL 사례), A-12_1(불량 1.0, PASS), N-9_1(λ 붕괴 WARN, 피크 7개 스파이크 사례). 각 8~9KB
- 프런트 연결 시 주의: 피크 label은 엔진 관례명(Rsei/Rct/W/미해결…) 그대로 — P1·R_SEI/P2·R_ct/P3·R_diff 표기 변환은 프런트 몫

## ★ 엔진 검증 요청 — τ축 shift 관련 (2026-08-31, 다음 엔진 세션이 처리할 것)
배경: 현 판정 기준은 진폭 축(R_ohm·R_SEI·R_ct·R_diff)+KK 잔차뿐 — DRT 피크의 τ 방향 이동 정보가 판정에 미반영. τ=R·C이므로 피크 이동은 정전용량·동역학 변화(조기 열화 신호) 또는 측정 조건 차이(온도)를 의미.
1. **Δlog τ 특징 추출**: 기준 대비 각 피크의 τ 위치 이동량을 특징값으로 추출, JSON 계약의 features에 추가 (peaks[]에 tau 있음 → 기준 정렬 후 편차 계산)
2. **피크 매칭 방식 검증**: P1/P2/P3 할당이 절대 τ 구간 기준이면 전역 shift 시 라벨 오배정 위험 — 상대 순서·기준 스펙트럼 정렬 기반인지 재확인
3. **λ 인공 shift 검증**: 파일별 자동 λ(L-curve) 차이가 피크 위치를 인위적으로 이동시키는지 확인 (동일 데이터에 λ 스윕해서 피크 τ 안정성 체크)
4. **전역/국부 구분 로직**: 전 피크 일괄 이동(→온도 등 측정 조건 의심, 품질 플래그) vs 특정 피크만 이동(→해당 계면 열화, 판정 특징) 분리. 온도 미기록(0/null) 파일에서 전역 shift 시 "측정 조건 확인" 플래그 출력
- UI 쪽은 표시 자리 준비됨(기여도 항목·품질 칩·피크 궤적 뷰) — 엔진 출력이 오면 연결만 하면 됨

## ★ 엔진 통합 대비 디자인 수정 목록 (2026-09-01, Zhang 외부 검증 결과 반영)

배경: 엔진 세션이 Zhang et al. 2020(Nat. Commun. 11, 1706) 실측 EIS로 외부 검증 완료(커밋 2c2d687, agentmemory `mem_mtgxccex_0dac9a0b7728`). 디자인에 영향 주는 확정 사실: TAU_BEYOND_WINDOW 경고 신설(품질 경고가 KK 단일→목록), EOL 국면 전환에서 피크 7개까지 실측, "고정 τ-창 피크 매칭은 취약 — 열화 피처는 피크 위치보다 대역별 저항 질량", peak_regions argmin 분할로 피크 면적 합=Rp 보장, τ shift는 실제 열화 신호로 검증(전하이동 피크 τ 2배 이동), 실측 R0=1774 mΩ 사례(극단값도 정상 데이터).

### 통합 전 필수
1. **품질 칩 → 경고 목록 구조**: 최고 심각도 + 개수 표시("경고 2건"), 펼치면 목록. 경고 코드→한국어 문구 매핑표 정의 (TAU_BEYOND_WINDOW → "측정 범위 밖 시상수 — 외삽 구간" 등)
2. **피크 5~7개 상태 설계**: P-라벨 매칭 무의미 국면 → 개별 라벨 포기, τ 대역 밴드 + "확산 지배 국면 전환" 배지로 전환 (EOL 판정 근거로 표출)
3. **축·컬러바 극단값 대응**: 자동 스케일 + 이상치의 컬러바 압축 방지 규칙 (퍼센타일 클램프 + 범위 밖 마커)

### 통합하면서
4. **대역 밴드 주 표현 승격**: τ구간 밴드에 대역명·대역 저항 합 표기, 기여도 문구도 "피크"→"대역" 전환 대비
5. **피크 음영 = 엔진 region 경계 사용**: 시각 추정 금지, JSON 계약에 `peaks[].region` + `warnings[]` 필드 추가 합의 필요

### 엔진 확인 대기 (검증 요청 4건 중 미답변)
6. Δlog τ 특징의 features 필드 추가(1번), λ 스윕 검증(3번), 전역/국부 shift 구분 로직(4번) — 2번(피크 매칭)은 "대역별 저항 질량" 교훈으로 답변됨
