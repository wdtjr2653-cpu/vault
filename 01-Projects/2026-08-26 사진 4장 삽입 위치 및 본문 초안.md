## 번호판 블러 처리 — **자동 처리 철회, 수동 작업으로 전환 (2026-08-26)**

> 아래 자동 블러는 결과가 사용자 기준에 못 미쳐 **되돌림**. 현재 `이정석_사진선정\`의 파일은 전부 **블러 미적용 원본**이며, 번호판 마스킹은 **사용자가 포토스케이프X 등으로 직접 수행**한다.
> 되살리려면 `build_panels.py`의 `MASK_PLATES = True`로 변경 후 재실행(측량된 좌표는 그대로 보존됨).
> 아래 기록은 재시도 시 참고용.

### (참고) 자동 블러 시도 이력

4개 패널 전체를 대상으로 판독 가능한 번호판을 **모두 마스킹**함(총 10건).

**방식(2차 개선)**: 1차 결과가 "검열한 티"가 나서 재작업. 원인은 ① NEAREST 확대로 생긴 블록 격자, ② 각진 사각 경계. 개선안은 BOX 다운샘플(정보 파괴, 복원 불가) → **BICUBIC** 확대 + 약한 가우시안(격자 제거) → **라운드 사각 + 페더링 마스크**로 합성. 결과가 피사계심도 아웃포커스처럼 보여 인위적이지 않음.

| 패널 | 마스킹한 번호판 |
|---|---|
| A | 우하 EV6 1건 (나머지 3컷은 번호판 미노출) |
| B | 없음 (측면·실내 컷이라 번호판 미노출) |
| C | 우측 EV9 1건 (좌측 컷은 미노출) |
| D | 6컷 전부 + 배경 차량 2건 = 총 8건 |

좌표는 `build_panels.py`의 `PLATES` 딕셔너리에 **원본 대비 비율**로 저장 — 패널을 재구성해도 블러가 따라감. 좌표는 격자 오버레이(`gridview.py`, `locate.py`)로 육안 확인해 지정하고, `verify_plates.py`로 원본 해상도에서 4배 확대해 판독 불가를 최종 확인.

**시행착오 기록 (재작업 시 주의)**
- 페더링을 쓰면 경계 부근 마스크 강도가 떨어져 **가장자리 문자가 살아남는다** → 마스크를 페더 반경만큼 **바깥으로 확장(outset)** 해 그려야 내부가 완전 불투명해짐.
- 페더 반경을 전 영역 공통(최댓값)으로 적용하면 **작은 영역이 뭉개져 마스크 강도가 미달**됨(배경 차량 번호판이 살아남았음) → **영역별로 개별 반경·개별 합성**해야 함.
- 안전하게 넓게 잡았더니 **범퍼까지 뿌옇게 번져** 부자연스러웠음 → `locate_all.py`로 각 번호판 4모서리 좌표를 원본 확대해 직접 읽고 **번호판 실경계로 재조정**. 페더는 `min(가로,세로)//10`, 마스크는 페더의 2배만큼 outset(가장자리에서도 완전 불투명 보장). 최종적으로 흐림이 번호판에만 붙어 있음.
