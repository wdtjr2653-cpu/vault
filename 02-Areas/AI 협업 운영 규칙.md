#area/ai-collaboration

## 개요
사용자는 Claude와 ChatGPT/Codex를 하나의 공동 작업 체계로 사용한다. 이 문서는 두 에이전트가 회사 PC(`LJS2653`)와 집 PC를 오가며 작업할 때 지켜야 할 공통 운영 규칙의 **기준 문서**다.

## 에이전트별 기본 역할
| 에이전트 | 우선 활용 영역 |
|---|---|
| Claude | Gmail·Drive 확인, 기존 맥락 파악, 문서 초안 작성, Obsidian 정리 |
| Codex | 코드 구현, 데이터 처리, 테스트·검증, Git 변경 관리 |

역할은 고정된 독점 영역이 아니라 작업 성격에 따라 조정 가능하다.

### Claude가 갖고 있고 Codex엔 없는 스킬 (2026-08-21 확인)
Codex는 이 사실을 몰랐다(설정 파일이 갈라져 있었음 — 아래 "설정 파일은 두 개다" 참고). 협업 작업 분배 시 참고:
- 문서 제작: Word/PPTX/Excel/PDF/HWP 파일 생성·편집
- 웹 아티팩트 퍼블리싱: 즉시 공유 가능한 HTML 대시보드/리포트 제작(예: 2026-08-21 토큰 비용 대시보드)
- 데이터 시각화 설계: 차트/컬러 시스템/접근성(색맹) 검증
- UI/UX·프론트엔드 디자인: 컴포넌트, 디자인 시스템, 배너·로고·아이콘
- 브라우저 자동화(Chrome 조작, 스크린샷, 폼 입력, 콘솔·네트워크 디버깅)
- 유튜브 등 영상 분석(자막·프레임 추출로 영상 내용 학습·요약)
- 웹 리서치(최신 정보 검색·페치)
- Gmail/Drive/Calendar 등 Google Workspace 직접 조작

GUI/시각적 결과물이 필요한 작업은 이 목록을 먼저 확인하고 Claude에게 배정을 고려할 것.

## 작업 시작 전 확인 순서
1. 현재 컴퓨터와 작업 위치 확인
2. agentmemory 검색
3. Obsidian 기준 문서(이 문서 포함) 확인
4. Git pull 여부 및 변경 상태 확인
5. 현재 작업 담당과 충돌 가능성 확인

## 회사·집 환경 구분
- 컴퓨터명 `LJS2653` = 회사 PC
- 그 외 컴퓨터 = 집 PC

### 세 저장소의 실제 공유 범위 (2026-08-21 실측 확인)
"각각 로컬이라 안 겹친다"가 아니라, **범위가 서로 다르다**:
| 저장소 | 같은 PC 안(Claude↔Codex) | 다른 PC(회사↔집) |
|---|---|---|
| **agentmemory** | ✅ 실시간 공유 — 같은 로컬 서버(`127.0.0.1:3111`)에 둘 다 접속함(`~/.codex/config.toml`의 `mcp_servers.agentmemory`로 확인) | ❌ PC마다 별도 서버·DB, 동기화 안 됨 |
| **Obsidian(`C:\vault`)** | ✅ 같은 폴더를 파일로 직접 읽고 씀 | ⏳ Git 커밋·push 이후에만 반영 |
| **Git 원격** | — | ✅ **유일한 크로스 머신 동기화 경로**, 커밋에 반영된 것만 |

- Codex는 agentmemory MCP 도구뿐 아니라 **자체 네이티브 메모리(`~/.codex/memories_1.sqlite`)도 따로 갖고 있음** — 명시적으로 agentmemory를 쓰라고 하지 않으면 자기 메모리만 쓸 수 있으니, 중요 결정은 agentmemory에도 저장하도록 확인할 것.
- **설정 파일은 두 개다**: Claude는 `C:\Users\MONA\.claude\CLAUDE.md`, Codex는 `C:\Users\MONA\.codex\AGENTS.md`를 읽는다. 서로 다른 파일이라 한쪽에만 규칙을 적으면 다른 쪽은 모른다 — 공통 규칙은 **양쪽 파일에 각각** 적어야 한다.
- Git에 반영된 파일만 회사·집 공통 공유 정보로 간주한다. Git에 없는 로컬 변경은 다른 환경에서 보이지 않는다.

## 동시 편집 방지
한 파일을 두 에이전트가 동시에 수정하지 않는다. 다른 에이전트의 미커밋 변경이나 확인되지 않은 결과물을 임의로 덮어쓰지 않는다.

## 작업 인계 시 남겨야 할 내용
작업을 마치거나 다른 에이전트/환경으로 넘길 때 다음을 기록한다:
- 수행한 작업
- 변경 파일
- 검증 결과
- 미완료 사항
- 다음 담당 에이전트

## 신뢰 기준
- 중요한 변경은 **Git에 반영된 문서를 최종 기준**으로 삼는다.
- 사용자나 프로젝트의 최신 상태와 충돌하는 오래된 정보(agentmemory, Obsidian, 로컬 파일 어디서든)가 발견되면 자동으로 믿지 말고, 실제 코드·Git 상태·사용자의 최신 지시로 재확인한다.

## agentmemory 사용 범위
agentmemory의 일반적인 조회·기록은 사용자가 지속적으로 허용했다. 다만 삭제, 외부 공개, 강제 덮어쓰기 등 파괴적 작업은 사용자에게 별도 확인한다.
