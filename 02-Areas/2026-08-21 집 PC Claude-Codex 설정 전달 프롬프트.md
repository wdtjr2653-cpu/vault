# 집 PC Claude–Codex 설정 전달 프롬프트

작성 위치: 회사 PC `LJS2653`  
실행 대상: 컴퓨터명이 `LJS2653`이 아닌 집 PC  
실행 순서: **Codex 프롬프트 먼저 완료 → Claude 프롬프트 실행**

이 문서는 회사 PC의 로컬 설정이나 agentmemory DB를 복사하기 위한 문서가 아니다. Git으로 공유된 운영 원칙을 집 PC의 각 에이전트 전역 MD와 로컬 agentmemory 연결 상태에 맞게 적용하기 위한 일회성 전달 프롬프트다.

## 1. 집 PC Codex에 전달할 프롬프트

```text
이 PC에 회사 PC(LJS2653)에서 확정한 Claude–Codex 공동 작업 체계와 harnessing 원칙을 적용해줘.

먼저 읽기 전용으로 환경을 확인해:
1. 컴퓨터명을 확인한다. LJS2653이면 집 PC가 아니므로 어떤 설정도 수정하지 말고 중단한다.
2. C:\vault의 Git 상태와 origin을 확인한다. 미커밋 변경이 없을 때만 `git pull --ff-only`로 최신 내용을 받고, 변경이 있으면 덮어쓰거나 stash하지 말고 충돌 가능성을 보고한다.
3. C:\vault\02-Areas\AI 협업 운영 규칙.md를 기준 문서로 읽는다.
4. 집 PC의 C:\Users\<현재사용자>\.codex\AGENTS.md와 agentmemory MCP 연결 설정을 확인한다. 회사 PC의 로컬 경로나 DB를 복사하지 않는다.

확인 후 다음 원칙을 집 PC Codex 전역 AGENTS.md에 **짧은 공동 작업 섹션으로만** 반영해. 이미 같은 내용이 있으면 중복 추가하지 말고, 기존 사용자 정보·코딩 규칙·다른 설정은 유지해.

- 사용자는 Claude와 Codex를 공동 작업 체계로 사용한다.
- LJS2653은 회사 PC, 그 외는 집 PC이며 Obsidian과 agentmemory는 PC별 로컬이다.
- 회사↔집 공통 상태는 Git 원격에 커밋·push된 내용만 인정한다.
- 순차 의존 작업은 한 에이전트가 끝까지 맡고, 파일과 기능이 독립적인 경우에만 분담한다.
- 한 파일을 동시에 수정하지 않고 다른 에이전트의 미커밋 변경을 덮어쓰지 않는다.
- 역할은 고정하지 않고 실제 커넥터, 로그인 세션, 작업 성격, 결과 품질로 정한다.
- 사용자는 매 작업을 두 에이전트에 각각 지시할 필요가 없다. 먼저 받은 에이전트가 단독/분담 가치를 판단하고, 분담 가치가 있을 때만 파일 범위와 다른 에이전트용 프롬프트를 제시한다.
- 인계 시 branch, commit, 변경 파일, 검증 결과, 미완료 항목, 다음 담당자를 기록한다.
- 중요 결정과 시행착오는 agentmemory MCP와 Obsidian에 남긴다. Codex 네이티브 메모리에만 저장하면 Claude와 공유되지 않는다.
- 이전 작업·과거 결정·인계가 필요한 경우 agentmemory를 우선 검색한다. 작업 분담·환경 이동·충돌 위험이 있을 때만 Obsidian의 AI 협업 운영 규칙을 읽는다.
- 최신 사용자 지시와 현재 코드·Git 상태가 오래된 메모리보다 우선한다.
- 컨텍스트가 약 70~80%에 가까워지면 편집·테스트 중간이 아닌 결정 경계에서 인계 내용을 먼저 기록한 뒤 compact한다.
- agentmemory 일반 조회·기록 권한은 지속 허용으로 취급하되 삭제·외부 공개·강제 덮어쓰기는 별도 확인한다. MCP 호스트가 도구별 승인을 다시 표시할 수 있다는 사실과 데이터 접근 권한을 혼동하지 않는다.

적용 후 검증해:
1. AGENTS.md 변경 diff를 보여주고 공동 작업 섹션 외의 변경이 없는지 확인한다.
2. agentmemory에서 `Claude Codex 공동 작업`을 읽기 전용 검색해 연결 여부만 확인한다.
3. C:\vault의 Git 상태와 기준 문서 최신 커밋을 보여준다.
4. 수정 파일, 추가한 줄 수, 검증 결과를 요약한다.

설정 과정에서 새 사실이 발견돼 AI 협업 운영 규칙.md를 바꿔야 한다면 먼저 내게 변경안을 보여주고 승인을 받아라. 자동으로 push하거나 회사 로컬 메모리를 집으로 복제하지 마라.
```

## 2. 집 PC Claude에 전달할 프롬프트

```text
Codex가 집 PC에 Claude–Codex 공동 작업 체계와 harnessing 원칙을 먼저 적용했다. 이제 Claude 쪽 로컬 설정을 같은 기준에 맞춰 검증·적용해줘.

먼저 읽기 전용으로 확인해:
1. 컴퓨터명을 확인한다. LJS2653이면 집 PC가 아니므로 어떤 설정도 수정하지 말고 중단한다.
2. C:\vault의 Git 상태를 확인한다. 미커밋 변경이 없을 때만 `git pull --ff-only`를 실행하고, 변경이 있으면 덮어쓰거나 stash하지 말고 보고한다.
3. C:\vault\02-Areas\AI 협업 운영 규칙.md와 C:\vault\02-Areas\2026-08-21 집 PC Claude-Codex 설정 전달 프롬프트.md를 읽는다.
4. 집 PC의 C:\Users\<현재사용자>\.claude\CLAUDE.md와 agentmemory MCP 연결을 확인한다. 회사 PC의 CLAUDE.md 전체나 로컬 agentmemory DB를 복사하지 않는다.

CLAUDE.md의 기존 사용자 정보와 규칙은 유지하면서, Codex의 AGENTS.md와 의미가 일치하는 **짧은 Claude–Codex 공동 작업 섹션**만 추가 또는 갱신해. 중복 문장은 만들지 마라. 반영할 핵심은 다음과 같다.

- LJS2653은 회사 PC, 그 외는 집 PC이고 Obsidian·agentmemory는 PC별 로컬이다.
- Git 원격에 커밋·push된 정보만 회사↔집 공통 상태다.
- 순차 작업은 한 에이전트가 끝까지 맡고 독립 파일·기능만 분담한다.
- 같은 파일 동시 편집과 다른 에이전트 미커밋 변경 덮어쓰기를 금지한다.
- 역할은 Claude/Codex 고정 독점이 아니라 실제 커넥터·로그인·작업 특성·결과 품질로 정한다.
- 사용자가 두 에이전트 모두에게 매번 프롬프트를 보낼 필요는 없다. 먼저 받은 에이전트가 단독/분담을 판단하고 필요할 때만 상대 에이전트용 범위가 명확한 프롬프트를 작성한다.
- 인계에는 branch, commit, 변경 파일, 검증 결과, 미완료 항목, 다음 담당자를 남긴다.
- 중요한 결정·시행착오는 agentmemory와 Obsidian에 기록하며, 현재 사용자 지시·코드·Git이 오래된 메모리보다 우선한다.
- 컨텍스트 70~80% 부근에서는 작업 중간이 아니라 결정 경계에서 인계를 기록한 후 compact한다.
- agentmemory 일반 조회·기록은 허용됐지만 삭제·외부 공개·강제 덮어쓰기는 별도 확인한다. 반복 승인 팝업은 MCP 도구 실행 승인 정책일 수 있으므로 기억 접근 권한 부족으로 단정하지 않는다.

적용 후 다음을 보고해:
1. CLAUDE.md에서 바뀐 공동 작업 섹션 diff
2. Codex AGENTS.md와 의미가 어긋나는 항목이 있는지
3. agentmemory에서 `Claude Codex 공동 작업` 읽기 전용 검색 결과 유무
4. C:\vault Git 상태와 수정 파일 목록

공통 기준 문서의 수정이 필요하다고 판단되면 직접 수정하거나 push하지 말고 변경안만 제시해. Codex가 이미 수정한 파일을 동시에 다시 편집하지 마라.
```

## 완료 확인

- 두 에이전트가 현재 PC를 집 PC로 정확히 인식한다.
- `AGENTS.md`와 `CLAUDE.md`의 공동 작업 규칙이 의미상 일치하고 중복이 없다.
- 회사와 집의 로컬 agentmemory DB를 같은 저장소로 오인하지 않는다.
- Git 커밋·push 전 로컬 변경을 다른 PC에서 보이는 정보로 간주하지 않는다.
- 이후 사용자는 작업을 한 에이전트에 먼저 요청하고, 그 에이전트가 단독 처리 또는 분담을 판단한다.
